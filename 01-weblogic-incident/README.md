# G사 WebLogic 서버 침해사고 분석

> SK쉴더스 루키즈 32기 개인 과제 · 2026.08 · 분석 보고서 20쪽 ([PDF 보기](weblogic-incident-report.pdf))

<br>

## 시나리오

"웹사이트가 갑자기 느려졌다"는 이용자 민원에서 시작하는 모의 침해사고입니다. 확인해 보니 DMZ 구간의 WebLogic 서버 CPU 사용률이 100%에 멈춰 있었고, 아래 아티팩트를 받아 원인을 거슬러 올라갔습니다.

| 아티팩트 | 내용 |
| --- | --- |
| IIS 액세스 로그 | 이틀치 (3.8GB, 137MB) |
| Windows 이벤트 로그 | Security.evtx, System.evtx |
| 네트워크 패킷 | 전체 구간 캡처 (pcapng) |
| MFT | analyzeMFT로 추출한 파일시스템 메타데이터 |

<br>

## 내가 한 일

- 네 가지 아티팩트를 시간 기준으로 맞춰 공격 과정을 8단계로 재구성했습니다.
- 분석과 보고서 작성은 혼자 했고, 전체 공격 흐름도만 팀원들과 화이트보드에 함께 그렸습니다.

<br>

## 재구성한 공격 흐름

| 단계 | 공격자가 한 일 | 근거 |
| --- | --- | --- |
| 1 | 웹 취약점 자동 스캐닝 (침해 전날) | IIS 로그 User-Agent (Nikto, Arachni, DirBuster, Skipfish) |
| 2 | CVE-2023-21839 (WebLogic T3/IIOP JNDI Injection)로 원격 코드 실행, 리버스 셸 연결 | 패킷 (T3 → LDAP → 리버스 셸 TCP 4444) |
| 3 | 백도어 계정 `infosechack` 생성, 관리자 그룹 추가 | 리버스 셸 평문 통신을 tshark hex dump로 추출 |
| 4 | frpc 리버스 터널 구축 (아웃바운드 7000 포트로 RDP 포워딩) | MFT에서 삭제된 `frpc.ini` 확인, EID 7045 |
| 5 | 백도어 계정으로 RDP 접속 | EID 4624 Logon Type 10 |
| 6 | Ladon, Mimikatz 실행 후 보안 로그 삭제 | `!start.bat`, EID 7045, EID 1102 |
| 7 | 내부 SQL 서버 접근, DB 파일 `infos.mdf`를 FTPS로 유출 | FileZilla 서버 로그, 패킷 |
| 8 | XMRig 채굴기 설치 → CPU 100% (민원의 직접 원인) | EID 7045, MFT |

<br>

## 분석하면서 짚은 점

- **로그 삭제도 기록이 남는다.** 공격자가 보안 로그를 지웠지만, 지운 행위 자체가 EID 1102로 남아 Mimikatz 실행 시점을 좁히는 단서가 됐습니다.
- **도구가 6주 전에 준비돼 있었다.** MFT에서 `ladon.zip` 내부 파일 타임스탬프가 침해 6주 전으로 나와, 즉흥적인 공격이 아니라 사전에 준비된 표적 공격(APT)으로 판단했습니다.
- **방화벽은 아웃바운드로 우회됐다.** 인바운드 RDP는 막혀 있었지만, 피해 서버가 밖으로 터널을 열어 우회했습니다. 아웃바운드 트래픽 모니터링이 필요하다는 근거로 정리했습니다.
- **조치 사항은 시급한 순서로 나눴다.** 패치와 계정 삭제처럼 바로 할 일, 1개월 안에 할 일, 3개월 안에 할 일로 나눠서 읽는 사람이 무엇부터 해야 하는지 알 수 있게 했습니다.

<br>

Wireshark, tshark, analyzeMFT, Windows 이벤트 로그 (evtx)
